# Portfolio: Ismail Azry

Personal portfolio for "Product Designer, Web & E-commerce | Shopify Design & Build". Audience: hiring managers for Product Designer, Design Technologist and Frontend UI Engineer roles in Malaysia. The code is part of the portfolio and will be read.

## Stack
- Astro + TypeScript, static output.
- Plain CSS with custom properties. Tokens live in `src/styles/tokens.css`, generated from `portfolio-content/tokens.md`. No Tailwind, no UI kits.
- Content collections for case studies, other works and fun. Loaded from `portfolio-content/` via glob loaders in `src/content.config.ts`; the folder name is the slug.
- Images through `astro:assets` (`<Image>`/`<Picture>`), AVIF/WebP with responsive `srcset`.
- Deploy: Vercel, auto-deploy from `main`.

## Source of truth
- Copy and frontmatter: `portfolio-content/**/index.md`. Do not rewrite copy; flag issues instead.
- Visual intent: `<!-- layout: ... -->` notes in the Markdown, plus `portfolio-content/references/*.png`.
- `references/` images are layout reference only. Never import or ship them. The folder is git-ignored.
- Brand assets that do ship: `portfolio-content/brand/` (`logo.svg`, `glyph-ia.svg` with paths `id="I"` and `id="A"`).
- Home page layout and hero motion: the Home layout section of `portfolio-content/site.md`.
- `tokens.md` and `references/` override any design skill's defaults. Use skills for craft, not brand choices.

## Rules
- Semantic HTML: one `h1` per page, landmarks, real lists, `figure`/`figcaption` for images.
- WCAG 2.2 AA: contrast, visible focus states, full keyboard access, `prefers-reduced-motion` respected.
- Responsive from 360 px. Mobile first. No horizontal scroll.
- No text baked into images except genuine UI screenshots. Every image has meaningful alt text.
- JS only where it earns it (hero glyph animation, lightbox, video play). Islands, not a SPA.
- Lighthouse 95+ on Performance, Accessibility, Best Practices, SEO.
- British/Malaysian spelling.
- Small components with one job. Name them by what they are (`CaseStudyMeta`, `PhoneFrame`, `FigureGrid`).
- Device frames are components, never images. PhoneFrame models the iPhone 17 Pro: screen ratio 1206:2622, outer corner radius about 13% of frame width, thin even black bezel (about 2.5% of width), aluminium edge as a 1–2px outer ring in a neutral grey, Dynamic Island as a black pill centred near the top (about 30% of screen width, 3% of screen height). A top safe-area strip (solid, empty band behind the Dynamic Island, default 6% of screen height, set by the `safeArea` prop, 0 to remove) keeps screenshot content below the island. No status bar, no side buttons, no shadow beyond one soft drop shadow. BrowserFrame: thin top bar with three dots, no URL text; the one exception is an optional short `label` after the dots (site · platform, e.g. "AT Auto Shoppe · Shopify"), used only by Lab. Screenshots fill the screen width exactly (width 100%, height auto), aligned top, clipped only at the bottom. Never crop the sides. One named exception: email screenshots may use PhoneFrame's `fitTo` (on an Other Works aside, `fitPhones: true` in `compositions.ts`, as in MBFW's Bridepay section), so the screen takes the email's height instead of the iPhone ratio and a short email leaves no empty band. App screens may not; they keep the iPhone ratio.
- Phone rows: from 600px, phones at their max width with a 48px gap, centred; in a narrow column they shrink evenly so the gap holds. Rows in one group (e.g. stage rows) can share a column count so phones match in size. Below 600px, a row of 2 sits 2 per row; a row of 3 or more becomes a snap row.
- Below 600px, rows of 2 images stack to one column and rows of 3 or more become a snap row, unless a layout note says otherwise. Uniform rows (logos) and single-column runs stay as they are.
- Snap rows (below 600px, the `.snap-row` utility in `global.css`): CSS only, one horizontal row with scroll snap. Two phones plus a peek, or one image (or one labelled group) plus about 16% of the next. The row runs out to the screen edges. Its affordance is the peek and a thin scrollbar; no "swipe" labels, counters or dots. Captions stay with their own figure, step numbers stay in step captions. Keyboard access comes through each slide's zoom link, so no extra tab stops. Applies to FigureGrid (and through it StageRows), ScrollSteps and LabelledStack.
- Case study hero: the h1 is the project name alone (`title`); an optional `subtitle` sits under it as a `<p>`, not a heading (the home card name and meta description don't use it). An optional `glance` (problem, did, outcome; one line each) sits directly under the h1 at every width, so a phone reader sees the outcome in the first screen. The outcome links to the stat cards chapter when the case study has one. `summary` stays the home card and meta description line. Below 600px the hero visual sits between the glance and the overview (title, glance, visual, overview, meta); from 600px it follows the copy (title, glance, overview, meta, visual); from 1200px the title and glance take columns 1–8 with the meta as hairline rows in 9–12, then the overview in 1–5 beside the visual in 7–12. The hero sits on the page cream: no accent band. The project `accent` appears only as the small square in each section label.
- Case study chapters: each `##` is a chapter (h2), numbered from its order by `ChapterHeader` (the overview in the hero is 01); never type a number into the heading (the build stops on a case study `##` that opens with one). A chapter's one-line subhead is a `> line` directly under its `##` (after its layout note), rendered as `<p class="subhead">`, never a blockquote or a heading. Headings run h1 > h2 (chapters) > h3 (subsections, stages). `<!-- layout: numbered rules -->` draws a list as `RuleList`: a real `<ol>`, number then rule, hairlines between rules. Stat cards take "Figure: label" or a bold figure; a line above them is their muted source, a line after them (blank line before it) is body.
- Scrolling steps (`<!-- layout: scrolling steps, sticky phone left -->` on a stage or a chapter, `ScrollSteps` + `scroll-steps.ts`): one run of phones, each image with its own italic caption as the step text (first sentence in semibold, step number in the accent red); the stage caption follows the last step. Every step holds its own phone and real `<img>`, nothing aria-hidden. Below 600px a snap row; from 600px phone beside text, hairlines between; without JS that layout holds at every width. From 900px with JS the phones share one sticky cell (columns 1–4) beside the scrolling texts (6–11); one IntersectionObserver sets `data-active` on the step at mid-viewport and CSS shows its phone (opacity crossfade only under `prefers-reduced-motion: no-preference`, instant otherwise). No extra tab stops: focusing a step's zoom link activates it and scrolls its text into view.
- Case study rhythm below 600px: sections 32px block padding with 24px between blocks (48 and 32 from 600px); stage rows 48px padding and 48px between stages, a hairline between stages. Stat cards are open cells under hairlines (no fill, no box), two per row with the lead (and an odd last card) across both; from 1200px the lead takes columns 1–7. Stacked tables show middle columns as "Name: value" lines and set the last column off with an accent rule. Heading sizes don't change. Scoped to case study components; other pages keep their own mobile spacing.
- Home work cards: each cover comes from `WorkCover`, one recipe for every case study. The tile is square (radius 0) on the page cream with a 1px hairline border and no colour fill, with the project's `hero` screenshot in its BrowserFrame or PhoneFrame rising from the bottom edge (clipped only at the bottom, no shadow); without `hero`, the `cover` image fills the tile. Under the cover go the project name (Sora semibold, sentence case as written), the optional `card_line` (one short line, never a truncated summary) and the case study's `glance.outcome` (no outcome, no line) as plain text, always visible. The outcome sits under a small "Outcome" label (Inter 600, uppercase, muted, one accent-red square before it, the card's only colour) in body colour, not bold, at most two lines at 360px; shorten the copy rather than let it run to three. There's no overlay; the link's name is the project name and its description is the outcome ("Outcome: …"), then the summary. Below 600px each card is a row: cover about 40% on the left, text on the right, hairlines between rows. From 600px the three cards share a row; from 900px each takes four of the twelve columns. Names never clip or truncate (16px keeps PLANETSTEWARDS on one line at 360px). Other Works and Fun are text links with an arrow (`ShortCard`, `.link-arrow`), one per row with a hairline above each, across the full content width from the left edge; they turn accent red and underline on hover and `:focus-visible`. Hover effects sit inside `(hover: hover)`, and the frame lift also needs `prefers-reduced-motion: no-preference`.
- Back to top: a text link (`BackToTop`), "Back to top" with a small up arrow, in the accent red (`--color-accent`, 5.75:1 on the page background; darken only if a token change drops it below 4.5:1), at the end of every page except home, 32px below the pager or last section and above the footer, linking to `#top` on `body`. Not a pill. It keeps the global focus ring. The jump is smooth only under `prefers-reduced-motion: no-preference`.
- Footer (every page, every width): a hairline across the content width, then two groups 32px apart. First, "Let's brew something together.", the email address in full as copyable text, then the contact links 16px below as 48px-tall outline buttons with an icon and a visible label (Email, LinkedIn, CV, Source code; 1px border, accent red fill on hover and `:focus-visible`). Second, the nav links (not on home) with the credit line 12px below. From 900px the first group takes columns 1–6 and the second columns 7–12, bottoms aligned. From 1200px the second group (nav and credit) aligns to the frame’s right edge; the only right-aligned text on the site. Bottom padding is 32px. Full width on home, the wide frame elsewhere.
- Lab (home, `LabSection` + `LabCard`): one folder per entry in `portfolio-content/lab/<slug>/` (`index.md` + `poster.png`); the clip is served as is from `public/videos/`, named in the frontmatter (`video`) with its measured pixel size (`video_size`), and the build stops if the file is missing. Each card, in order: the clip in `MotionVideo` with `frame="browser"` and the frame's bar label (`frame_label`), its BrowserFrame at the clip's own ratio, the poster cropped from the top to match (full width, clipped only at the bottom); the name (h3, Sora semibold); the build time as a pair, the number in Sora bold `--text-32` and the unit in small uppercase tracking, singular for 1 ("1 WEEK", "2 WEEKS"), after a visually hidden "Build time:"; one `line` of copy; the tools as outline text pills in a wrapping `ul` (not links, no icons); and a `.link-arrow` (the case study, or the repo in a new tab). There's no visible caption: what the clip shows is the video's accessible name (`video_label`). Below 600px one card per row with hairlines between; from 600px two per row (six of twelve columns from 900px), the cards' parts on shared subgrid rows so names line up. Copy is facts only: no hype, no "AI-powered".
- MotionVideo: muted, loop, playsinline, `preload="none"`; plays only while near the viewport (IntersectionObserver) and only under `prefers-reduced-motion: no-preference`; otherwise the poster stays with a Play button. The poster is a lazy `<Picture>` over the video (never the `poster` attribute, which loads with the page) and hides once the video plays. The Play/Pause toggle is a small round icon pill (40px, 44px hit area) in the frame's bottom-right corner, cream fill with a black glyph and border, inverted on hover and focus, `aria-label` "Play clip"/"Pause clip"; it stays available while a clip plays.
- Buttons: the primary CTA ("See the work", `.button-primary`) is the only pill (`--radius-pill`). Controls (Shuffle, lightbox buttons) are square outline buttons (`.button-square`, radius 0, 1px border). The one other round control is MotionVideo's play/pause, a small icon pill. Lab's tool tags are pills too, but they are text, not controls. Navigational links that used to be pills (Other Works, Fun, the live site link, the 404's way back) are text links with an arrow (`.link-arrow`). Text links (nav, inline, "Previous", Back to top) stay text. Home work cards are not buttons.
- Widths (tokens in `tokens.md`): `.container` is the wide frame by default (`--content-wide` 1600px, side gutters 24px, 48px from 900px, `--gutter-wide` 100px from 1200px), so a component that misses a class stays capped. Home (hero, Selected work, footer) and the sticky header opt in to `.container--full` (no cap, 16px gutters, 24px from 600px). Running text, captions and the home about stay at `--measure` (68ch); images, figure grids, headings and the hero headline take the full width. Anything that bleeds to the screen edge uses `--page-gutter`, which the container sets; `--gutter` is the column gap only.
- Header: 16px block padding (about 24px of air with the links' own padding), its 1px bottom border the only rule; the first section under it opens with space, not a hairline. `--header-h` in `global.css` holds its measured height.
- Swiss system (every page): a 12-column grid from 900px (`.grid-12`, gutter-wide gaps; 4 columns from 600px, 1 below); components place parts by column span, not their own fractions. Text is flush left, ragged right: no centred or justified text. Sections open with a 1px hairline (`--rule`, `.section-rule`, or `.container-rule` on a `.container`), except About on home, where the GlyphBand above is the divider, and list rows are separated by hairlines between rows, never above and below every row. Each section has a numbered label (`SectionLabel`, Inter 600, 14px, uppercase): numbered per page from 01, never hand-typed; it shows "01 / Selected work" when the label adds information and the number alone (hidden from screen readers) when it would only repeat the heading. Hierarchy comes from scale: `--text-name` (the home name, about 92–180), `--text-hero` (48–128), `--text-display` (page h1, 32–80), `--text-section` (h2, 32–48), labels 14. Radius 0 on cards, frames, covers, figures and controls; PhoneFrame and DisplayFrame keep their hardware corners and colour swatches stay circles. No orange, no decorative grid lines, no marquee.
## Workflow
- Plan before building any new page or component; wait for approval.
- Build one case study fully before templating the rest.
- Run `npm run build` and fix all errors and warnings before saying a step is done.
- One commit per finished step, imperative message.
